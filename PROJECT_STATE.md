## Architecture summary

Implemented on feature/appointment-booking (pull request #2; design in docs/system-design.md): ASP.NET Core (.NET 10) modular monolith. Domain holds the rules (UTC half-open `TimeRange`, `BookingPolicy`, `ResourceAllocator`); Application holds `BookAppointmentHandler` (up to three attempts) and the `IBookingStore` and `IAppointmentQueries` ports; Infrastructure implements them with EF Core and Npgsql, with a migration adding three exclusion constraints on confirmed appointments (bay, technician, vehicle) and a seeder; Api exposes `POST /appointments` and `GET /appointments/{id}` as minimal APIs with Problem Details, OpenAPI and Scalar. Runs with Docker Compose (API and PostgreSQL 18); CI on GitHub Actions. Planned in later changes: cancellation and availability, OpenTelemetry to the Aspire Dashboard with health checks, idempotent booking.
